# Runtime Regression Gate

This gate provides a deterministic, headless release check for `godot-project/` gameplay/runtime behavior.

## What It Covers

- Startup and autoload sanity (`GameModes`, `GameState`, `EventBus`, `AudioManager`, `ParticleManager`)
- Overworld movement and encounter transition flow
  - Encounter payload consistency (`source`, `encounter_hex`, `combat_id`, `time_limit`)
  - Encounter transition timing budget checks
- Combat feel-critical invariants:
  - LMB attack responsiveness and cadence
  - Combo tier payoff checks (damage scaling and armor-break unlock progression)
  - Rapid LMB spam cooldown-gating/cadence edge cases
  - RMB shield hold/release state transitions
  - Rapid RMB toggle shield/collision-state coherence
  - Perfect-block timing window behavior vs normal hold-block
  - Projectile normal-block consume vs perfect-block reflect outcomes
  - Perfect-block reduced shield HP loss vs normal block
  - Hotline-style movement behavior
  - Shield/projectile outcomes
  - Victory/defeat transition paths
- Save/load resilience and corrupt-save quarantine recovery
- Existing smoke and combat regression suites

## Run Locally

From repo root:

```bash
bash godot-project/scripts/run_runtime_release_gate.sh
```

Primary outputs are written to:

- `godot-project/artifacts/runtime-gate/runtime_gate_summary.json`
- `godot-project/artifacts/runtime-gate/runtime_gate_report.md`
- `godot-project/artifacts/runtime-gate/logs/`

The runner also copies user-data artifacts generated by Godot:

- `combat_metrics_latest.json`
- `runtime_regression_metrics_latest.json`
- `runtime_regression_comparison_latest.json`

## Update Baseline

To refresh the committed runtime baseline from current metrics:

```bash
bash godot-project/scripts/update_runtime_regression_baseline.sh
```

This runs the deterministic harness and overwrites:

- `godot-project/tests/runtime_gate/baselines/runtime_regression_baseline.json`

Use this only when behavior changes are intentional and reviewed.

## Interpreting Failures

1. Check `runtime_gate_summary.json` for failed step IDs.
2. Open the step log under `godot-project/artifacts/runtime-gate/logs/`.
3. For baseline mismatches, inspect `runtime_regression_comparison_latest.json`:
   - `regressions`: human-readable failures
   - `comparison_results`: per-metric actual vs baseline/threshold window and rule metadata/delta
4. If mismatch is expected, update baseline with the script above; otherwise fix regression and rerun gate.
